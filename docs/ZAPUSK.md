# Запуск бота для новичков

Идея простая: арендуем маленький сервер (компьютер в интернете), копируем на него бота и запускаем.
Так вам ничего не нужно устанавливать на свой компьютер, а бот работает круглосуточно.

Все команды ниже вводятся **в окне терминала, подключённого к серверу** (шаг 3). Не в Telegram и не в этом чате.

## Шаг 1. Создайте бота в Telegram (5 минут)

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите «Запустить».
2. Отправьте `/newbot`.
3. Введите название бота (любое, например «Тайный покупатель»).
4. Введите username: латиница, обязательно заканчивается на `bot` (например `mystery_shopper_uz_bot`).
5. BotFather пришлёт **токен**: длинная строка вида `123456789:AAH...`. Скопируйте и сохраните в заметки. Это пароль от бота, никому его не показывайте.
6. Узнайте свой Telegram ID: найдите **@userinfobot**, нажмите «Запустить». Он пришлёт число (`Id: 123456789`). Сохраните его.

## Шаг 2. Арендуйте сервер (10 минут)

Подойдёт любой хостинг, где можно взять сервер с **Ubuntu 24.04**. Рекомендую Hetzner (около 4 EUR в месяц).

1. Зайдите на https://www.hetzner.com/cloud и зарегистрируйтесь (нужна банковская карта и подтверждение личности).
2. Создайте проект: кнопка **New project**, любое имя.
3. Внутри проекта нажмите **Add Server** и выберите:
   - **Location**: любая европейская (Falkenstein, Nuremberg или Helsinki);
   - **Image**: **Ubuntu 24.04**;
   - **Type**: **Shared vCPU**, самый дешёвый тариф;
   - **Networking**: оставьте по умолчанию;
   - **SSH keys**: ничего не добавляйте, тогда пароль пришлют на почту;
   - остальное не трогайте.
4. Нажмите **Create & Buy now**.
5. Через минуту сервер появится в списке. Запишите его **IP-адрес** (например `95.216.1.2`). Пароль root придёт на вашу почту.

## Шаг 3. Подключитесь к серверу

**Windows 10/11:** нажмите кнопку Пуск, наберите `PowerShell`, откройте.
**Mac:** откройте программу «Терминал».

В открывшемся окне введите (замените IP на свой) и нажмите Enter:

```
ssh root@95.216.1.2
```

- На вопрос `Are you sure you want to continue connecting?` ответьте `yes`.
- Введите пароль из письма. **Символы пароля при вводе не отображаются**, это нормально. Лучше вставить пароль правой кнопкой мыши.
- Сервер сразу попросит придумать новый пароль: введите старый, затем дважды новый.
- Когда увидите приглашение вида `root@ubuntu-...:~#`, вы на сервере. Дальше все команды вводятся здесь.

Если ssh не работает: на странице сервера в Hetzner есть кнопка консоли (значок `>_` справа вверху), это тот же терминал прямо в браузере.

Вставка в терминал: правая кнопка мыши (Windows) или Cmd+V (Mac).

## Шаг 4. Установите Docker (2 минуты)

Введите по одной команде:

```
apt-get update && apt-get install -y git
curl -fsSL https://get.docker.com | sh
```

Дождитесь окончания (побегут строки текста). Проверка:

```
docker --version
```

Должна показаться версия Docker.

## Шаг 5. Скачайте бота

```
git clone -b claude/telegram-secret-shopper-bot-v9tvy7 https://github.com/iinikolov-cpu/botech.git
cd botech
```

Если git просит логин и пароль, значит репозиторий закрытый. Самый простой выход: на GitHub откройте репозиторий, Settings, внизу Danger Zone, Change visibility, Public. В коде нет паролей и токенов (они хранятся только на сервере), поэтому это безопасно. Потом повторите команду.

## Шаг 6. Впишите настройки

```
cp .env.example .env
nano .env
```

Откроется простой текстовый редактор. Стрелками переместитесь и допишите значения после `=` (без пробелов и кавычек):

```
BOT_TOKEN=123456789:AAH...ваш токен
FIRST_ADMIN_ID=123456789   <- ваш Telegram ID из шага 1
```

Остальные строки не трогайте. Сохранить: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**.

## Шаг 7. Запустите

```
docker compose up -d --build
```

Первый раз это займёт 2-4 минуты (идёт сборка). В конце должно быть `Started`.

Посмотрите, что бот жив:

```
docker compose logs
```

Ищите строку `"msg":"бот запущен"`. Если вместо неё ошибка, смотрите раздел «Если что-то не так».

## Шаг 8. Проверьте в Telegram

1. Откройте своего бота (ссылка из BotFather) и нажмите «Запустить». Так как вы первый админ, бот ответит приветствием.
2. Отправьте `/admin`: должна появиться панель с кнопками.
3. Нажмите **Инвайты**, затем **На 1 чел.**: бот покажет ссылку-приглашение.
4. Отправьте ссылку с другого аккаунта Telegram (друг, второй телефон) и нажмите «Запустить». Тот аккаунт увидит «Заявка отправлена».
5. Вам придёт сообщение «Новая заявка» с кнопками. Нажмите **Одобрить**.
6. Второй аккаунт получит «Заявка одобрена».
7. Проверка закрытого доступа: с третьего аккаунта напишите боту что угодно. Ответ должен быть только «Нет доступа».

## Полезные команды (всегда из папки `botech`)

| Что сделать | Команда |
|---|---|
| Посмотреть логи вживую (выход Ctrl+C) | `docker compose logs -f` |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose down` |
| Обновить до новой версии | `git pull && docker compose up -d --build` |

Если вы закрыли терминал и зашли заново: `ssh root@ВАШ_IP`, затем `cd botech`.

База данных хранится в отдельном томе Docker и не пропадает при обновлениях.

## Если что-то не так

- **Бот молчит.** Выполните `docker compose logs` и посмотрите последние строки.
- **`не задана переменная BOT_TOKEN` или `FIRST_ADMIN_ID должна быть числом`.** Вы не сохранили `.env` или ошиблись. Откройте `nano .env` и проверьте: без пробелов и кавычек.
- **`Unauthorized` в логах.** Токен скопирован неверно. Возьмите новый у BotFather (`/mybots`, выбрать бота, API Token).
- **`команда не найдена: docker`.** Шаг 4 не завершился, повторите его.
- **После `/admin` тишина.** Ваш ID в `FIRST_ADMIN_ID` не совпадает с реальным. Проверьте у @userinfobot, поправьте `.env` и выполните `docker compose up -d`.

## Проверка этапа 2: сценарии и задания

Для проверки нужны вы (админ) и хотя бы один одобренный покупатель (второй аккаунт из шага 8).

**Обновите бота на сервере** (из папки `botech`):

```
git pull
sudo docker compose up -d --build
```

**1. Загрузите сценарий**
1. Отправьте боту `/admin`, нажмите **📋 Сценарии**, затем **📄 Скачать шаблон**. Бот пришлёт файл `scenario_template.yaml`.
2. Откройте файл на телефоне или компьютере (подойдёт Блокнот), поменяйте текст под свой сценарий. Поле `key` должно быть уникальным.
3. Отправьте этот файл боту в чат (кнопка-скрепка, «Файл»/«Документ»).
4. Бот ответит «Сценарий создан (версия 1)». Если в файле ошибка, бот перечислит, что исправить.
5. Чтобы изменить сценарий, поправьте файл (оставив тот же `key`) и отправьте снова: появится версия 2. Уже выданные задания останутся на старой версии.

**2. Назначьте задание**
1. В админ-панели нажмите **➕ Назначить**.
2. Выберите сценарий, затем срок (дни на выполнение считаются **после принятия**), затем отметьте покупателя(ей) и нажмите **🚀 Отправить**.
3. Покупатель получит инструкцию с кнопками **Принять** и **Отказаться**.

**3. Проверьте со стороны покупателя**
1. Нажмите **✅ Принять**: покажется срок «выполнить до». Вам, как админу, придёт уведомление.
2. Кнопка **📝 Отправить отчёт** запускает отчёт (см. «Проверка этапа 3» ниже).
3. Команда `/tasks` у покупателя показывает список его заданий.

**4. Посмотрите у админа**
**📌 Задания**: список с фильтрами. В карточке задания видна вся история (создано, отправлено, принято и время).

## Проверка этапа 3: промокоды, отчёты, компенсации

Обновление, как обычно: `git pull`, затем `sudo docker compose up -d --build`. Новые таблицы в базе создадутся сами, данные сохранятся.

**1. Как работают промокоды**
- Каждый код можно использовать несколько раз. Сколько раз, задаёт переменная `PROMO_LOW_THRESHOLD` в файле `.env` (по умолчанию 1). Одинаково для всех кодов.
- На каждое задание выдаётся **один** код. Пока задание активно (принято и не выполнено), этот код не достанется никому другому.
- **Использованием считается выполненное задание** (отчёт отправлен). После этого код возвращается в оборот, если использования ещё остались. Если админ **отменил** задание, код возвращается в оборот без списания использования.
- Кнопки «код использован» в админке больше нет: всё считается автоматически.

**2. Загрузка, список и удаление**
1. Админ-панель, **🎁 Промокоды**, **➕ Загрузить коды**. Отправьте один код или пачку сообщением (по одному в строке) либо файлом `.csv` / `.txt`. Повторы и мусор бот отсеет.
2. **📋 Список кодов** показывает таблицу: код, сколько раз его ещё можно использовать («Осталось») и активное задание, за которым он закреплён сейчас («Задание», «нет», если код свободен).
3. **🗑 Удалить коды**: один или несколько кодов (отправьте список) либо все незанятые. Код, закреплённый за активным заданием, не удаляется. История выдач сохраняется.
4. Когда покупатель принимает задание, ему сразу приходит код. Если свободного кода нет, задание всё равно принимается, покупатель видит «Промокод пока недоступен» и может нажать **🎁 Получить промокод** позже.

**Предупреждения админу**
- «Все промокоды заняты активными заданиями»: есть коды с остатком использований, но все закреплены за заданиями, а новое задание ждёт код.
- «Не осталось ни одного промокода со свободными использованиями»: приходит, когда покупатель принимает задание при пустом пуле, а также сразу после отчёта, который израсходовал последнее использование.

Чтобы задать лимит, на сервере в папке `botech` откройте `nano .env`, добавьте или измените строку `PROMO_LOW_THRESHOLD=3` (пример: код можно использовать 3 раза), сохраните (Ctrl+O, Enter, Ctrl+X) и выполните `sudo docker compose up -d`.

**3. Отчёт покупателя**
1. В карточке принятого задания нажмите **📝 Отправить отчёт**.
2. Бот задаёт вопросы чек-листа по одному: оценка и да/нет кнопками, текст сообщением, фото и видео присылаются в чат. Необязательные вопросы можно пропустить, назад можно вернуться кнопкой, отменить весь отчёт тоже.
3. В конце бот спрашивает про компенсацию: сумма (например `150000` или `150 000`) и фото чека. Реквизиты не запрашиваются.
4. Итоговый экран со всеми ответами, затем **✅ Отправить отчёт**. Отправленный отчёт изменить нельзя. Если срок вышел, отчёт всё равно принимается с пометкой «после срока».
5. Начатый, но не отправленный отчёт сохраняется: можно закрыть Telegram и продолжить позже с того же места.

**4. Админ: отчёты и компенсации**
1. При получении отчёта админам приходит уведомление. **📄 Открыть отчёт** сначала присылает фото и видео (альбомом, по 10 штук), а **последним сообщением** ответы и кнопки решения, поэтому кнопки всегда внизу.
2. **✅ Проверено** принимает отчёт (статус «проверено»).
3. **↩ На доработку** возвращает отчёт покупателю: бот просит написать любой комментарий, что нужно исправить. Покупатель получает комментарий и кнопку «📝 Исправить отчёт», заполняет отчёт заново и отправляет. Появляется новая версия отчёта (старые сохраняются), срок за исправление опозданием не считается. **Сумму и чек компенсации заново вводить не нужно:** они остаются как были, а на итоговом экране есть кнопка «✏ Изменить компенсацию», если что-то надо поправить. Если компенсацию админ отклонил, новые сумма и чек обязательны.
4. **💰 Компенсации**: вкладки «К выплате», «Отклонено», «Выплачено» с общей суммой. Карточка компенсации это одно сообщение: фото чека, а данные и кнопки прямо под ним.
5. **💵 Выплачено** просит подтверждение, после чего покупателю уходит сообщение о выплате.
6. **✖ Отклонить** отклоняет компенсацию с вашим комментарием (например, сумма не совпадает с чеком). Покупатель получает комментарий и кнопку «💰 Исправить компенсацию», присылает новую сумму и чек, и компенсация возвращается в «К выплате». Отклонённую выплатить нельзя.
7. Значок ⚠ у компенсации означает, что тот же файл чека уже прикладывали к другому заданию.

**Раздел «Отчёты» в заданиях.** В нём видны отчёты, ждущие проверки, возвращённые на доработку, а также принятые, но ещё не закрытые по компенсации (не выплачена или отклонена). Когда компенсацию выплатили (или её нет), задание уходит во вкладку «Закрыто».

**Повторное назначение.** Один и тот же сценарий можно назначать одному покупателю сколько угодно раз. Если у него уже есть незавершённое задание по этому сценарию, бот сообщит об этом в итоге назначения. Задания различаются номерами (#12).

## Удаление и отмена заданий

В карточке задания (**📌 Задания**, выбрать задание) кнопка зависит от статуса:
- **Создано, отправлено, отказ:** кнопка **🗑 Удалить задание**. Задание исчезает вместе с историей, перед этим бот просит подтверждение. Действие записывается в журнал админов. У покупателя старые кнопки этого задания перестают работать.
- **Принято, просрочено, на доработке:** кнопка **🚫 Отменить задание**. Задание остаётся в истории со статусом «отменено», покупатель получает уведомление и не может отправить отчёт. Закреплённый за заданием промокод возвращается в оборот без списания использования.
- **С полученным отчётом (отчёт получен, проверено):** не удаляется и не отменяется, потому что данные нужны для учёта и выплат.

После удаления или отмены тот же сценарий можно снова назначить этому покупателю.

## Этап 4: просрочка, напоминания, ручной пинг, бэкап

Обновление, как обычно: `git pull`, затем `sudo docker compose up -d --build`. Миграция базы применится сама.

### Автоматическая просрочка
Когда срок принятого задания (дни после принятия) выходит, а отчёта нет, бот сам ставит статус «просрочено»:
- покупатель получает сообщение: срок вышел, но отчёт всё ещё можно отправить (он будет отмечен «после срока»);
- админу отдельное уведомление не приходит: такие задания видны во вкладке **📌 Задания → Просрочено** и помечены ⚠ в общем списке.

### Напоминания покупателям
Админам напоминания и «эскалации» не приходят. Покупателю бот напоминает сам, а админ смотрит на отметки ⚠ в списке **📌 Задания** (и в карточке задания):
- «нет ответа 1 дн. 3 ч»: задание отправлено, а покупатель не ответил дольше порога;
- «просрочено на ...»: срок отчёта вышел;
- «на доработке 1 дн. 2 ч»: отчёт возвращён, а покупатель не исправил дольше порога.

Всё это настраивается **в файле `.env` на сервере**, в минутах (в боте этих настроек нет):

| Переменная | Что значит | По умолчанию |
|---|---|---|
| `REMIND_ACCEPT_MINUTES` | когда напоминать, если задание отправлено, а ответа нет (минуты после отправки) | `1440,2880` (24 и 48 часов) |
| `REMIND_REPORT_MINUTES` | когда напоминать об отчёте (минуты после принятия и после возврата на доработку) | `1440,2880` |
| `REMIND_QUIET_HOURS` | тихие часы: ночью напоминания не уходят, а переносятся на утро. Формат `22-9` или `off` | `22-9` |
| `STALE_MINUTES` | после скольких минут ожидания в списке появляется отметка ⚠ | `1440` |

Список минут пишется по возрастанию, не больше 5 значений. `off` отключает напоминания. После правки `.env` выполните `sudo docker compose up -d`, чтобы бот перечитал настройки.

- Отправленные напоминания записываются в историю задания.
- Если бот долго не работал, покупатель получит **одно** (последнее) напоминание, а не несколько подряд.
- Состояние хранится в базе: после перезапуска бота ничего не повторяется.

### Настройки (⚙ Настройки в админ-панели)
Здесь только время ежедневного бэкапа (`03:00` или `off`) и кнопка «Бэкап сейчас». Нажмите «✏ Время бэкапа» и отправьте новое значение сообщением.

### Чистота чата
В чате у каждого одно «живое» меню: когда вы открываете новый экран или присылаете ответ (коды, комментарий, файл), прежнее меню и ваше сообщение удаляются. Предупреждение о промокодах всегда одно. Уведомления (новое задание, «принял задание») остаются, пока вы не нажмёте в них кнопку: тогда сообщение превращается в меню.

### Ручное напоминание
- В карточке задания: **🔔 Напомнить покупателю**.
- В карточке покупателя: **🔔 Напомнить о заданиях** (по всем его незавершённым заданиям).
- Не чаще одного раза в 10 минут по одному заданию, чтобы случайно не завалить покупателя сообщениями.

### Ежедневный бэкап базы
- Каждый день в заданное время (по умолчанию 03:00) бот присылает **первому админу** файл `bot-ДАТА.db.gz`: согласованную копию базы, сделанную без остановки бота.
- Последние 7 копий также хранятся на сервере в томе, в папке `backups` (число меняется `BACKUP_KEEP` в `.env`).
- Кнопка **💾 Бэкап сейчас** в настройках делает копию по запросу.
- **Важно:** в копии персональные данные покупателей (имена, ID, отчёты). Храните файлы в надёжном месте и никому не пересылайте. Фото и видео в копию не входят: они хранятся в Telegram.
- Если Telegram не принимает файл (больше 50 МБ), бот сообщит, а копия останется на сервере.

### Восстановление из копии
Нужно, если сервер потерян или база испорчена. Команды выполняются на сервере в папке `botech`.
1. Скачайте файл копии из Telegram на компьютер и загрузите на сервер (команда на **вашем компьютере**): `scp bot-20261001-030000.db.gz ИМЯ@IP_СЕРВЕРА:~/`
2. На сервере распакуйте: `gunzip bot-20261001-030000.db.gz`. Получится файл `bot-20261001-030000.db`.
3. Остановите бота: `sudo docker compose down`.
4. Узнайте имя тома: `sudo docker volume ls` (обычно `botech_botdata`). Если тома нет (новый сервер), сначала выполните `sudo docker compose up -d --build` и затем `sudo docker compose down`, тогда он создастся.
5. Положите копию на место базы (подставьте имя тома и файла):
   ```
   sudo cp bot-20261001-030000.db /var/lib/docker/volumes/botech_botdata/_data/bot.db
   sudo rm -f /var/lib/docker/volumes/botech_botdata/_data/bot.db-wal /var/lib/docker/volumes/botech_botdata/_data/bot.db-shm
   sudo chown 65532:65532 /var/lib/docker/volumes/botech_botdata/_data/bot.db
   ```
6. Запустите бота: `sudo docker compose up -d` и проверьте `/admin`.

### Как проверить этап 4 быстро
Ждать сутки не нужно. В `.env` поставьте `REMIND_ACCEPT_MINUTES=1,2`, `STALE_MINUTES=2` и `REMIND_QUIET_HOURS=off`, затем `sudo docker compose up -d`. Назначьте задание и не отвечайте: через минуту придёт напоминание, через две второе, а в списке заданий появится отметка ⚠ «нет ответа». Потом верните значения по умолчанию.

## Этап 5: статистика и выгрузка обратной связи

Обновление: `git pull`, затем `sudo docker compose up -d --build`. Миграция базы не нужна.

### Статистика (кнопка 📊 Статистика в /admin)
Период переключается кнопками: 7 дней, 30 дней, всё время (считается по дате создания задания). На экране:
- сколько заданий выдано, принято, отклонено, отменено, ждут ответа, в работе, просрочено;
- сколько отчётов получено и проверено;
- среднее время от принятия до отчёта;
- компенсации: к выплате и выплачено (количество и суммы);
- по каждому оператору: выдано, отчётов, просрочено, среднее время, **средняя оценка по каждому вопросу-оценке** и **доля «да»** по вопросам да/нет.

Считается по последней версии отчёта (если отчёт возвращали на доработку, учитывается исправленный).

### Выгрузка в CSV (📤 Выгрузить в CSV)
Бот присылает файл, который открывается в Excel и Google Таблицах (кодировка и разделитель «;» уже настроены).
- **Задания:** все задания периода, даты этапов, число напоминаний, промокод, компенсация.
- **Ответы по сценарию:** одна строка на отчёт, **по колонке на каждый вопрос чек-листа**. Это и есть сводная обратная связь: оценки, да/нет и комментарии покупателей рядом. Выбираете сценарий, потому что у разных сценариев разные вопросы.
- **Компенсации:** суммы и статусы.
- **Журнал админов:** последние 5000 действий.

Фото и видео в таблицу не попадают (они хранятся в Telegram), в ячейке стоит «фото приложено». Сами файлы смотрите в боте: Задания → Открыть отчёт.
