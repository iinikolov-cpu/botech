# Бот «Тайный покупатель»: установка и работа, инструкция для новичков

Это единая инструкция: от нуля до работающего бота, затем ежедневная работа, обновление, копии базы и что делать при проблемах. Программировать не нужно. Все команды вводятся в окне терминала, подключённого к серверу (шаг 4), а не в Telegram.

**Что получится.** Бот работает на арендованном сервере круглосуточно. Вы (админ) назначаете задания покупателям, бот выдаёт промокоды, собирает отчёты и данные для компенсации, напоминает покупателям, присылает копию базы и считает статистику.

**Что понадобится.** Аккаунт в Telegram, банковская карта для аренды сервера (около 4 EUR в месяц), 40 минут времени.

---

## Часть 1. Установка

### Шаг 1. Создайте бота в Telegram
1. В Telegram найдите **@BotFather** (с синей галочкой), нажмите «Запустить».
2. Отправьте `/newbot`, введите название (любое) и username (латиница, обязательно заканчивается на `bot`).
3. BotFather пришлёт **токен** вида `123456789:AAH...`. Сохраните его в заметки. Это пароль от бота, никому его не показывайте.
4. Найдите **@userinfobot**, нажмите «Запустить». Он пришлёт ваш Telegram ID (число). Сохраните его.

### Шаг 2. Арендуйте сервер
Подойдёт любой хостинг с сервером на **Ubuntu 24.04 или новее** (например Hetzner, DigitalOcean, любой местный). Нужен самый дешёвый тариф: 1 ядро, 1 ГБ памяти, 10 ГБ диска. Запишите **IP-адрес** сервера и данные для входа (логин и пароль придут на почту или покажутся на странице сервера).

### Шаг 3. Что такое «терминал»
Терминал это окно, куда вводят текстовые команды. Откройте его на своём компьютере:
- **Windows 10/11:** Пуск, наберите `PowerShell`, откройте.
- **Mac:** программа «Терминал».

Вставка текста: правая кнопка мыши (Windows) или Cmd+V (Mac). Пароль при вводе не показывается, это нормально.

### Шаг 4. Подключитесь к серверу
В терминале введите (подставьте свой логин и IP) и нажмите Enter:

```
ssh ЛОГИН@ВАШ_IP
```

Логин чаще всего `root` или `ubuntu`. На вопрос `Are you sure you want to continue connecting?` ответьте `yes`. Введите пароль. Когда увидите строку вида `ЛОГИН@имя-сервера:~$`, вы на сервере.

Если вошли не под `root` (в строке заканчивается на `$`), перед командами `docker` ниже ставьте слово `sudo`, как в примерах. Если вошли под `root`, `sudo` можно не писать, но и с ним всё работает.

Запасной вариант: у многих хостингов есть кнопка веб-консоли прямо на странице сервера.

### Шаг 5. Установите Docker и Git
Вводите команды по одной и дожидайтесь окончания:

```
sudo apt-get update && sudo apt-get install -y git
curl -fsSL https://get.docker.com | sudo sh
sudo docker --version
```

Последняя команда должна показать версию Docker.

### Шаг 6. Скачайте бота

```
git clone -b claude/telegram-secret-shopper-bot-v9tvy7 https://github.com/iinikolov-cpu/botech.git
cd botech
```

Если git просит логин и пароль, репозиторий закрытый. Либо сделайте его временно публичным (на GitHub: Settings, внизу Danger Zone, Change visibility; в коде нет паролей, они хранятся только на сервере), либо создайте токен доступа GitHub и используйте его вместо пароля.

### Шаг 7. Впишите настройки

```
cp .env.example .env
nano .env
```

Откроется текстовый редактор. Стрелками перейдите к нужным строкам и впишите значения после `=` (без пробелов и кавычек):

```
BOT_TOKEN=токен_из_шага_1
FIRST_ADMIN_ID=ваш_ID_из_шага_1
```

Сохранить: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**. Остальные настройки описаны ниже в части 3, пока их можно не трогать.

Закройте файл с токеном от чужих глаз (чтобы его не мог прочитать другой пользователь сервера):

```
chmod 600 .env
```

### Шаг 8. Запустите

```
sudo docker compose up -d --build
sudo docker compose logs
```

Первый запуск занимает 2-4 минуты. В логах должна быть строка `бот запущен`. Если там ошибка, см. часть 5.

### Шаг 9. Проверьте
1. Откройте своего бота в Telegram, нажмите «Запустить». Затем отправьте `/admin`: появится админ-панель.
2. Нажмите **🎟 Инвайты**, затем **На 1 чел.**: бот покажет ссылку-приглашение.
3. Откройте ссылку с другого аккаунта Telegram и нажмите «Запустить». Аккаунт увидит «Заявка отправлена».
4. Вам придёт «Новая заявка». Нажмите **Одобрить**.
5. С третьего (неприглашённого) аккаунта бот должен отвечать только «Нет доступа».

Бот работает. Дальше настроим его под вашу программу.

## Часть 2. Первая настройка и ежедневная работа

### Сценарий (задание)
1. `/admin`, **📋 Сценарии**, **📄 Скачать шаблон**. Бот пришлёт файл `scenario_template.yaml`.
2. Откройте его в Блокноте, замените текст на свой: оператор, шаги инструкции, вопросы чек-листа. Типы вопросов: `text`, `rating` (оценка 1-5), `yesno`, `photo`, `video`. Поле `key` уникально для каждого сценария.
3. Отправьте файл боту как документ. Бот ответит «Сценарий создан» или перечислит ошибки.
4. Чтобы изменить сценарий, поправьте файл (тот же `key`) и отправьте снова: будет новая версия. Уже выданные задания остаются на старой.

### Промокоды
1. **🎁 Промокоды**, **➕ Загрузить коды**: отправьте коды сообщением (по одному в строке) или файлом `.csv`/`.txt`.
2. Каждый код можно использовать несколько раз (задаётся `PROMO_MAX_USES` в `.env`, по умолчанию 1). На каждое задание выдаётся один код, пока задание активно, этот код никому больше не достанется. Использованием считается отправленный отчёт.
3. **📋 Список кодов** показывает таблицу с остатком использований и активным заданием. Коды можно удалять по одному, списком или все свободные.
4. Бот предупредит, если все коды заняты или закончились.

### Покупатели
**🎟 Инвайты** создают ссылки-приглашения. Заявки приходят вам с кнопками «Одобрить» и «Отклонить». Покупателей можно блокировать в карточке. Другие админы добавляются командой `/addadmin ID`, снимаются `/rmadmin ID`.

### Задания
1. **➕ Назначить**: сценарий, срок (дни на выполнение, считаются от принятия), покупатели, **🚀 Отправить**.
2. Покупатель видит инструкцию и кнопки «Принять» или «Отказаться». После принятия сразу получает промокод.
3. Покупатель нажимает **📝 Отправить отчёт** и отвечает на вопросы по шагам. В конце вводит сумму и фото чека для компенсации (реквизиты не нужны).
4. В **📌 Задания** фильтры: все, ждут, в работе, отчёты, просрочено, закрыто. Значок ⚠ в списке означает, что покупатель слишком долго не реагирует (нет ответа, просрочено, висит на доработке).
5. Откройте отчёт: бот покажет фото и видео, затем ответы и кнопки. **✅ Проверено** принимает отчёт, **↩ На доработку** просит исправить (с вашим комментарием, компенсацию повторно вводить не нужно).
6. **💰 Компенсации**: чек и сумма одним сообщением. **💵 Выплачено** (после подтверждения покупателю уйдёт уведомление) или **✖ Отклонить** с комментарием.
7. Задание можно удалить (пока оно не началось) или отменить (когда идёт). Код при отмене возвращается в оборот.
8. Кнопка **🔔 Напомнить** в карточке задания или покупателя отправляет покупателю ручное напоминание (не чаще раза в 10 минут).

### Статистика и выгрузка
**📊 Статистика**: выдано, принято, выполнено, просрочено, средняя оценка по операторам и вопросам, доля «да», среднее время выполнения, суммы компенсаций. Период: 7 дней, 30 дней или всё время.

**📤 Выгрузить в CSV**: задания, **ответы по сценарию** (одна строка на отчёт, колонка на каждый вопрос: это сводная обратная связь), компенсации, журнал админов. Файлы открываются в Excel и Google Таблицах. Фото и видео в таблице отмечены словом «приложено», сами файлы смотрите в боте.

### Что делает бот сам
- Срок задания вышел: статус «просрочено», покупатель получает уведомление (отчёт всё равно можно сдать, он будет с пометкой «после срока»).
- Напоминает покупателям по расписанию из `.env` (часть 3), ночью не пишет.
- Каждый день присылает вам файл копии базы.
- Чистит чат: у каждого одно «живое» меню, прежние экраны и ваши служебные сообщения удаляются.

## Часть 3. Настройки в файле `.env`

Открыть: `cd botech` и `nano .env`. После изменения примените: `sudo docker compose up -d` (без `--build`).

| Переменная | Что значит | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от BotFather (обязательно) | нет |
| `FIRST_ADMIN_ID` | ваш Telegram ID, первый админ (обязательно) | нет |
| `TZ_NAME` | часовой пояс для времени в сообщениях и тихих часов | `Asia/Tashkent` |
| `LOG_LEVEL` | подробность логов: debug, info, warn, error | `info` |
| `PROMO_MAX_USES` | сколько раз можно использовать каждый промокод (прежнее имя `PROMO_LOW_THRESHOLD` тоже работает) | `1` |
| `REMIND_ACCEPT_MINUTES` | когда напоминать, если задание отправлено, а ответа нет (минуты после отправки, список по возрастанию, до 5 значений, `off` отключает) | `1440,2880` |
| `REMIND_REPORT_MINUTES` | когда напоминать об отчёте (минуты после принятия и после возврата на доработку) | `1440,2880` |
| `REMIND_QUIET_HOURS` | тихие часы: напоминания не уходят ночью, а переносятся на утро. `22-9` или `off` | `22-9` |
| `STALE_MINUTES` | через сколько минут ожидания в списке заданий появляется ⚠ | `1440` |
| `BACKUP_KEEP` | сколько последних копий базы хранить на сервере | `7` |

Время ежедневной копии (по умолчанию 03:00) меняется в боте: `/admin`, **⚙ Настройки**.

Быстро проверить напоминания: поставьте `REMIND_ACCEPT_MINUTES=1,2`, `STALE_MINUTES=2`, `REMIND_QUIET_HOURS=off`, примените, назначьте задание и не отвечайте. Потом верните значения.

## Часть 4. Обслуживание

Все команды из папки `botech` (`cd botech`).

| Что сделать | Команда |
|---|---|
| Посмотреть логи вживую (выход Ctrl+C) | `sudo docker compose logs -f` |
| Перезапустить | `sudo docker compose restart` |
| Остановить | `sudo docker compose down` |
| Запустить | `sudo docker compose up -d` |
| Посмотреть, что работает | `sudo docker compose ps` |

### Обновление до новой версии
```
cd botech
git pull
sudo docker compose up -d --build
```
Данные не теряются, база хранится в отдельном томе Docker. Нужные изменения базы бот применяет сам при запуске.

### Копии базы
- Каждый день в заданное время бот присылает **первому админу** файл `bot-ДАТА.db.gz` (согласованная копия без остановки бота). Последние копии лежат и на сервере.
- Кнопка **💾 Бэкап сейчас** в настройках делает копию по запросу.
- В копии персональные данные покупателей (имена, ID, отчёты). Храните файлы в надёжном месте. Фото и видео в копию не входят: они хранятся в Telegram и открываются через бота.
- Важно: копии в Telegram это ваша единственная страховка от потери сервера. Не удаляйте эти сообщения и периодически сохраняйте файлы на свой компьютер.

### Восстановление из копии (сервер потерян или база испорчена)
1. Скачайте файл копии из Telegram на компьютер и загрузите на сервер командой на **вашем компьютере**: `scp bot-20261001-030000.db.gz ЛОГИН@ВАШ_IP:~/`
2. На сервере: `gunzip bot-20261001-030000.db.gz`
3. Остановите бота: `cd botech && sudo docker compose down`
4. Узнайте имя тома: `sudo docker volume ls` (обычно `botech_botdata`). На новом сервере сначала выполните `sudo docker compose up -d --build`, затем `sudo docker compose down`, чтобы том создался.
5. Положите копию на место базы (подставьте имена):
```
sudo cp ~/bot-20261001-030000.db /var/lib/docker/volumes/botech_botdata/_data/bot.db
sudo rm -f /var/lib/docker/volumes/botech_botdata/_data/bot.db-wal /var/lib/docker/volumes/botech_botdata/_data/bot.db-shm
sudo chown 65532:65532 /var/lib/docker/volumes/botech_botdata/_data/bot.db
```
6. Запустите: `sudo docker compose up -d`, проверьте `/admin`.

### Посмотреть данные в базе
Самый безопасный способ: скачайте копию базы (см. выше), распакуйте на компьютере и откройте бесплатной программой **DB Browser for SQLite**. Рабочую базу на сервере руками лучше не трогать. Для отчётов есть статистика и CSV в боте.

### Начать с чистой базы (удалить все тестовые данные)
Необратимо: пропадут пользователи, задания, сценарии, промокоды. Сначала сделайте копию кнопкой «Бэкап сейчас».
```
cd botech
sudo docker compose down
sudo docker volume rm botech_botdata
sudo docker compose up -d
```
(Имя тома проверьте командой `sudo docker volume ls`.)

### Переезд на другой сервер
Сделайте копию базы кнопкой, установите бота на новом сервере (часть 1), затем выполните восстановление из копии. Старый сервер после этого остановите (`sudo docker compose down`), иначе два бота с одним токеном будут мешать друг другу.

## Часть 5. Если что-то не так

Сначала всегда: `sudo docker compose logs` и смотрите последние строки.

| Проблема | Что делать |
|---|---|
| `permission denied ... docker.sock` | Добавьте `sudo` перед командой `docker` |
| `не задана переменная BOT_TOKEN` или `FIRST_ADMIN_ID должна быть числом` | Не сохранён `.env` или опечатка. `nano .env`, без пробелов и кавычек |
| `Unauthorized` в логах | Неверный токен. Возьмите новый у BotFather (`/mybots`, ваш бот, API Token) |
| Бот не отвечает на `/admin` | `FIRST_ADMIN_ID` не совпадает с вашим ID. Проверьте у @userinfobot, поправьте `.env`, `sudo docker compose up -d` |
| `REMIND_...: нужно целое число минут` и подобное | Ошибка в значении настройки в `.env`, формат смотрите в части 3 |
| Бот молчит после перезагрузки сервера | `sudo docker compose up -d` из папки `botech` (обычно запускается сам) |
| Конфликт `terminated by other getUpdates request` | Тот же токен запущен ещё где-то. Остановите лишний экземпляр |
| Покупатель не получил задание | Он не нажал «Запустить» у бота или заблокировал бота. В карточке задания будет «не доставлено», после исправления нажмите **🔁 Отправить повторно** |
| Кончилось место на диске | `sudo docker system prune -f`, уменьшите `BACKUP_KEEP` |

## Безопасность в двух словах
- Токен и `.env` никому не показывайте и не выкладывайте. Файл `.env` не попадает в GitHub.
- Пускайте покупателей только по инвайтам. Лишних заблокируйте в карточке пользователя.
- Хранилище и копии содержат персональные данные: ограничьте круг людей с доступом к серверу и копиям.
- Обновляйте систему сервера раз в месяц-два: `sudo apt-get update && sudo apt-get -y upgrade`.
